## Безопасное обновление с GitHub

Создан ручной GitHub Actions workflow .github/workflows/publish-manual.yml. Он доступен только с основной ветки main, не запускается автоматически и требует подтверждения publish-vputipoputka.ru.

Для прямого SSH-доступа настроить в GitHub Actions secrets (ключи и пароли не отправлять в чат):
- POPUTI_DEPLOY_HOST: адрес сервера в AdminVPS.
- POPUTI_DEPLOY_USER: отдельный SSH-пользователь с ограниченным разрешением sudo -n на выполнение команды публикации.
- POPUTI_DEPLOY_SSH_KEY: приватный SSH-ключ технического пользователя.
- POPUTI_DEPLOY_KNOWN_HOSTS: предварительно проверенный SSH host key сервера (не получать слепо из неизвестного источника).
- POPUTI_DEPLOY_PORT: необязательно, по умолчанию 22.

Тогда GitHub → Actions → Publish Po Puti (manual, verified backup, rollback) → Run workflow → main → подтверждение.

Если секретов нет, workflow остановится без подключения к VPS.

## Что проверяет release-on-vps.sh

1. Сервис работает, ожидаемая база /var/lib/po-puti/po-puti.sqlite существует, папка /opt/po-puti находится в чистой Git-ветке main.
2. Целевой коммит — fast-forward от установленного кода.
3. До остановки приложения создаётся отдельная согласованная резервная копия SQLite WAL в /var/backups/po-puti. Проверяется целостность и читаемость таблиц.
4. Обновляются только код приложения и служба po-puti; затем проверяются локальный и HTTPS API.
5. При сбое новой версии возвращается предыдущий код и перезапускается приложение.

Не изменяются Nginx, firewall, DNS, MTU/MSS, сертификаты и системные пакеты.

**Ограничение:** откат кода не отменяет записи в БД, сделанные новой версией после запуска. Backup хранится на том же VPS, отдельная внешняя копия дополнительно необходима.

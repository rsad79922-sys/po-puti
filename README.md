# «По пути» — прототип 0.2 для Android + PWA

Совместные междугородние поездки по России. Сохранён фирменный дизайн: тёмно-синий, бирюзовый, светлые карточки и нижняя навигация.

## Состав архива

- `www/` — один мобильный интерфейс для PWA и Android, без платного UI-фреймворка;
- `server/server.mjs` — общая серверная часть Node.js 22+ с SQLite, регистрацией, заявками, сообщениями, отзывами, уведомлениями и разграничением прав;
- `tests/smoke-api.mjs` — автоматическая проверка обмена данными между двумя аккаунтами;
- `capacitor.config.json` — исходная конфигурация сборки Android.

## Что обновлено

1. Удалены фразы «Без комиссии в демоверсии» и «Один аккаунт для обеих ролей».
2. На карточках опубликованных поездок видны рейтинг и количество отзывов. Нажатие на рейтинг открывает отзывы водителя. В локальной демоверсии есть примеры отзывов. На сервере оценки появляются после поездок от подтверждённых пассажиров.
3. «Мои поездки»: **Будущие / Прошедшие / Отменённые**, без вкладок по ролям; заявки водителя выводятся под его поездкой.
4. Кабинет администратора в профиле **только при роли `admin`**: статистика, пользователи, поездки и жалобы, ручная отмена поездки. Право проверяется на сервере.
5. Вход / регистрация: **только логин и пароль**. Номер телефона необязателен при создании аккаунта; после заполнения профиля доступен подтверждённому участнику.
6. Подтверждение заявки открывает двусторонний чат и кнопку телефонного звонка (если номер добавлен). До подтверждения эти действия недоступны.
7. Карточка поездки из поиска, истории, уведомлений или админки открывает её подробности с **планом поездки**, встроенным виджетом Яндекс.Карт, точками и кнопкой открытия маршрута в Яндекс.Картах. Встроенная карта требует интернет и может блокироваться браузером; текстовый план и внешняя ссылка остаются.
8. Android и PWA работают с **одним API и одной базой**, когда оба подключены к запущенному серверу; синхронизация данных происходит при действиях и периодическом обновлении (15 секунд при открытом приложении).
9. Сервер предотвращает повторную заявку, повторное принятие заявки при отсутствии мест и повторную публикацию поездки с тем же идентификатором операции.

## Режим 1 — локальная демоверсия (без сервера)

В каталоге проекта:

```bash
python3 -m http.server 8080 --directory www
```

Откройте `http://localhost:8080`. Это только локальный пример: данные хранятся в браузере и **не синхронизируются между устройствами**.

Демопрофили: `maria`, `alex`, `irina`, `timur`, `admin-demo`; у всех только в локальной демонстрации пароль `demo1234`. В демоверсии возможно переключение тестовых пользователей в профиле, включая администратора. Настоящий сервер не создаёт эти демоаккаунты.

## Режим 2 — общий сервер (проверка межплатформенной работы)

Понадобится Node.js **22+** с доступным модулем `node:sqlite` (в Node 22 он ещё экспериментальный). В каталоге проекта:

```bash
# Настройте переменные окружения безопасным способом, вне Git-репозитория:
# ADMIN_USERNAME = логин будущего администратора
# ADMIN_PASSWORD = его отдельный стойкий пароль (не включайте в код)
# PORT = 8080
# HOST = 127.0.0.1
npm run server
```

Сервер выдаёт интерфейс по `http://127.0.0.1:8080/`, автоматически переключая его на общий API. Администратор создаётся **только при первом запуске с `ADMIN_USERNAME` и `ADMIN_PASSWORD`**. Эти переменные не нужно добавлять в `config.js`, отправлять по переписке или хранить в GitHub.

Проверка API из второго терминала:

```bash
node tests/smoke-api.mjs
```

Тест создаёт два временных аккаунта, публикует поездку, оформляет и принимает заявку, проверяет приватность телефона и чат, защиту административного API и отмену.

### Подключение PWA и Android к одному серверу

**PWA:** опубликуйте проект за HTTPS reverse proxy, например `https://app.ваш-домен.ru`, который пересылает запросы на локальный порт сервера. При выдаче страницы с сервера его `/config.js` сам включает общий API.

**Android:** перед созданием APK измените `www/config.js` в Android-сборке:

```js
window.PO_PUTI_BACKEND = true;
window.PO_PUTI_API_BASE = 'https://app.example.ru';
```

Замените домен на **один и тот же сервер API**, который использует PWA. Разрешите Android-origin `https://localhost` (он включён в примерный `APP_ORIGINS` на сервере). Нужен действующий HTTPS-сертификат. На устройствах должно быть соединение с сервером.

Если PWA и Android запущены лишь в автономной демоверсии, их данные **не будут общими**.

## Подготовка Android

```bash
npm install
npm run android:add
npm run android:sync
npm run android:open
```

Требуются Android Studio, Android SDK/JDK. Соберите debug APK в Android Studio и проверьте вход, карту и звонок на реальном телефоне. Готового APK/AAB в архиве нет.

## Безопасность и ограничения текущей версии

Сервер — **первый рабочий MVP для внутреннего тестирования**, а не готовая к публичному запуску система. Реализованы `scrypt`-хеширование паролей, случайные токены с хранением хешей на сервере, разграничение ролей, проверка подтверждений перед чатом, idempotency и серверная база, но **до публичного запуска нужны**:

- HTTPS на домене, контроль конфигурации CORS и безопасное хранение ключей;
- перенос пользовательских токенов из `localStorage` в более защищённый механизм (HttpOnly cookies для PWA и защищённое хранилище Android), защита от XSS/CSRF, усиленная защита входа;
- стабильная производственная БД (например PostgreSQL), резервное копирование, мониторинг и миграции;
- проверка лицензионных условий карт, реальная геокодировка, промежуточные остановки и маршрутизация;
- системные push-уведомления, проверка ролей в интеграционных тестах, нагрузочные тесты, модерация и защита от злоупотреблений;
- необходимые пользовательские соглашения и политика обработки персональных данных.

Пока уведомления внутри приложения обновляются при синхронизации. SMS, системные push, платёжный шлюз, реальный трекинг автомобиля и turn-by-turn-навигация **не подключены**. Яндекс.Карты открываются для подробного автомобильного маршрута, но приложение не заменяет навигатор во время движения.

**Не размещайте демопароли и секреты администратора в опубликованном репозитории.** Образцы тестовых учётных записей в статической демоверсии не действуют на сервере.

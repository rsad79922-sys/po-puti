## Автоматические проверки

Команды и результаты локальной проверки:

- `npm ci --ignore-scripts` — чистая установка по lock-файлу.
- `npm audit --audit-level=moderate` — 0 известных уязвимостей на момент проверки; это не доказательство отсутствия неизвестных уязвимостей.
- `npm run verify` — синтаксис JS/shell, **15 изолированных suites**, сборка `dist/`. Включает старые regression tests, новый security-hardening, isolated smoke, backup/restore и симуляцию release.
- Chromium — **4 browser suites**: cookie/XSS/cross-tab logout; полный сценарий двух пользователей; фото; SW offline/recovery/новая вкладка.
- WebKit — те же **4 browser suites** с реальным движком WebKit, не подменённым Chromium.
- Оба Nginx-шаблона — `nginx -t` с временным сертификатом, без запуска сервиса. Локально Nginx 1.26; штатный Ubuntu 1.24 проверяет CI.
- systemd-analyze — проверены временные копии unit в user-manager с единственной заменой /usr/bin/node на фактический локальный Node. Проверка исходных unit в system-manager предусмотрена Ubuntu CI.
- actionlint 1.7.11 и ShellCheck 0.10 — workflow и новые/изменённые эксплуатационные shell scripts; `git diff --check`.

Локальная среда — Debian 13, Node 24.22.1. WebKit 27.2 / Playwright 1.65.1 потребовал библиотек, которых не было в ОС: они скачаны/распакованы только в /tmp; временная копия launch wrapper получила этот library path. Проверка ldconfig обходилась только для этого локального запуска, сами browser assertions не отключались. В GitHub Actions WebKit устанавливается штатно `playwright install --with-deps webkit` на Ubuntu 24.04. Физические iPhone/Android и промышленная нагрузка не проверены.

Все изменяющие API-тесты работают на новых временных SQLite-базах. Симуляция release подменяет пути на временный каталог и systemctl/curl — на заглушки, проверяя отказ до остановки, откат после ошибки HTTPS и успешное обновление SHA. Она проверяет сохранность записей и фотографии. Старый standalone smoke-api не включается напрямую в suite: его запускает isolated wrapper.

## Оставшиеся ограничения и риски

- Android хранит Bearer в WebView localStorage. Совместимость старых APK сохранена; перед публичным запуском нужен отдельный Android Keystore-переход и новый APK. PWA уже использует HttpOnly cookie.
- Дата/время поездки не содержит часового пояса. Клиент использует время устройства, часть серверных проверок — UTC/время сервера. Автоматически менять трактовку существующих поездок нельзя: нужна согласованная схема хранения зоны/UTC и миграция. До этого избегайте использования по разным часовым поясам и проверяйте пограничные часы вручную.
- `/state` возвращает все подходящие будущие поездки и часть истории; пагинации нет. Индексы уменьшают чтение, но не ограничивают размер ответа. Нужны нагрузочные измерения, квоты пользователей и дальнейшая пагинация/антиспам.
- Один Node-процесс и SQLite на локальном диске. Без сетевого FS и cluster mode. Изменения схемы в этом PR добавочные; будущие несовместимые миграции потребуют отдельного плана rollback.
- Нет верификации телефона, системных push, платежей, автоматической модерации, восстановления пароля и полноценного пользовательского правового комплекта. Карты требуют внешнего доступа и проверки условий поставщика. Фото публичны по случайному URL — это не приватное файловое хранилище.
- Backup не удаляет старые копии: оператор должен контролировать диск, шифрование, offsite и retention. Внешний сбой, замеченный только runner после успешной проверки с VPS, помечает job failed и требует расследования, без удалённого автоматического data restore.
- Старый ZIP в releases — исторический артефакт, не источник для установки новой версии. Реальный APK/AAB не выпускался. Новая CI-сборка debug APK проверяется отдельно.
- Периодические TLS-сбои из прежних отчётов не воспроизведены/не диагностированы через SSH этим аудитом. Новые Nginx-шаблоны исправляют ошибки конфигурации установки, но не доказывают устранение внешнего сетевого инцидента.

Результат — проверяемое усиление MVP и воспроизводимый путь установки/обновления. Отчёт не объявляет систему безусловно готовой для неограниченного публичного использования.

## Дополнительная проверка GitHub Actions после открытия PR

В первом запуске Verify на Ubuntu 24.04 прошли test-build (npm ci/audit, 15 suites, dist) и Chromium. Nginx 1.24.0 проверил оба исходных шаблона успешно. Проверка unit обнаружила отсутствие /usr/bin/node в hosted runner; job теперь явно устанавливает Node 24 и создаёт этот путь в одноразовой CI-машине. Production unit и инструкция установки NodeSource не меняются.

Существующий внешний production-monitor в [запуске 43610455732](https://github.com/rsad79922-sys/po-puti/actions/runs/43610455732) получил 12/12 отказов TCP-подключения к vputipoputka.ru:443 (DNS и pinned IPv4, TLS 1.2/1.3), curl exit 7, HTTP 000. Это происходило до TLS-handshake и не доказывает ошибку сертификата. DNS runner указывал 130.49.129.99. Причина на VPS/firewall/маршруте без дополнительной диагностики не установлена; параметры production не менялись. Это отдельный неуспешный внешний check, его нельзя считать пройденным тестом кандидата или скрывать успешной локальной сборкой.

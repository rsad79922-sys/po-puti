# Прямая установка и обновление По пути

Одна ссылка для распространения: **https://vputipoputka.ru/install.html**.
На Android в браузере она показывает скачивание из `ANDROID_DOWNLOAD_URL`.
На iPhone/iPad — инструкцию установки PWA через Safari. PWA доступна также
на Android и компьютере. Скачивание APK и вызов установки PWA происходят
только после нажатия. Переход на поездку по существующим ссылкам не меняется.

## Как получает обновления пользователь

Подписанный APK с механизмом обновлений проверяет публичный
`/downloads/android-release.json` при запуске/возвращении в приложение
(не чаще раза в 15 минут). Логин, токен и контакты в эту проверку не передаются.
Ручная проверка: **Профиль → Настройки → Проверить обновления**.
Новая версия предлагается только при большем `versionCode`, том же пакете
`ru.poputi.app`, том же сертификате установленного APK и HTTPS-ссылке нашего сайта.
Кнопка «Позже» откладывает напоминание об этой версии на 24 часа; ручная проверка
доступна сразу. Ошибка сети не мешает работе приложения.

Кнопка «Обновить» открывает скачивание в браузере. Пользователь открывает
скачанный APK и подтверждает системную установку поверх приложения.
При необходимости Android запрашивает разрешение установки из этого источника.
Android проверяет цифровую подпись APK. Не надо удалять приложение или очищать
данные. Фоновая/тихая установка без согласия не реализуется.

Старые APK без механизма проверки надо один раз обновить вручную с сайта.
PWA получает новые ресурсы через Service Worker при соединении с сервером;
её обновление не обновляет нативную оболочку APK.

## Выпуск следующей версии

1. Внести код в отдельной ветке. Выполнить `npm run verify`, браузерные тесты
   Chromium/WebKit и Android CI. Слить проверенный PR в `main`.
2. Дождаться обычного развёртывания той же ревизии backend.
3. Запустить `android-direct-release.yml` на `main`, указав новые
   `version_code`, `version_name`, `publish_download=true`.
4. Workflow собирает релиз, подписывает **существующим** ключом на VPS,
   проверяет пакет/подпись/байты, тестирует Android 15 и Android 11 без GMS,
   проверяет обновление с текущего публичного APK и сохранение тестовых
   настроек. Только затем публикует файл и публичный манифест.
5. Проверить HTTPS `/install.html`, `/downloads/android-release.json`,
   `/downloads/po-puti.apk` и соответствие SHA-256 артефакту Actions.

Фиксированная ссылка `/downloads/po-puti.apk` всегда ведёт на текущий релиз.
Манифест указывает неизменяемый `/downloads/po-puti-<versionCode>.apk`, поэтому
открытое предложение не начнёт скачивать другую версию при новом выпуске.
Повторное использование номера, понижение версии и смена сертификата запрещены
публикатором. Предыдущие APK сохраняются в каталоге распространения.
Публикация сохраняет закрытую резервную копию старого APK, манифеста и настроек;
при неудачной проверке работоспособности восстанавливает их. База, фото,
пользовательские аккаунты и настройки сторонних интеграций не изменяются.

Манифест не содержит секретов. Каталог `/var/lib/po-puti-downloads` принадлежит
root, приложение может читать файлы, но не заменять APK. Service Worker не
перехватывает никакие `/downloads/` запросы.

## Ключ и резервная копия

Постоянный keystore: `/etc/po-puti/android-signing/po-puti-release.p12` на VPS.
Пароль хранится отдельно в защищённом файле того же каталога и не передаётся
в GitHub или журналы. Ключ не пересоздавать. Пакет не менять.
Владелец должен сохранить зашифрованную резервную копию keystore из
`/var/backups/po-puti-android-signing/` на отдельном защищённом носителе;
пароль — отдельно от копии. Потеря ключа лишит возможности обычного обновления.

Выпуск с сайта не изменяет старую заявку RuStore. Фоновые push остаются отдельной
интеграцией: без проекта FCM/RuStore и настройки доставки они не заработают
от появления механизма обновлений. Перед продвижением нужно завершить проверку
лицензии действующего геокодера и правовых текстов.

# По пути: поиск, серии, реклама и подготовка Android

Это обновление существующего приложения. Backend, SQLite, фотографии, подтверждения и отзывы общие. Production и RuStore автоматически не обновляются из рабочей ветки.

## Новые функции

* `/api/search?from=…&to=…&date=YYYY-MM-DD&type=private|bus|all`: источники раздельны. Частные результаты пагинируются по 50 с курсором и снимком времени создания, без пропуска при отмене записи предыдущей страницы, автобусы имеют отдельный nextOffset. Ошибки внешнего источника не являются пустой выдачей.
* `/api/search/places?q=…`: настоящий справочник Яндекс Расписаний, поддержка неоднозначных станций и кириллицы. Не подставляйте придуманные коды. Для импорта используется официальный `stations_list`; он тоже расходует квоту.
* `/api/admin/v5/external`: защищённые сведения об ошибках внешнего API и очереди lifecycle, без ключей/URL запросов; `/api/admin/v5/deletion-requests`: очередь запросов удаления для согласованной обработки.
* `/api/series`: создание до семи календарных дней включительно. Обязательны privateRide, weekdays, seriesEnd и clientKey. Все экземпляры создаются транзакционно; места и коммуникации независимы. Повтор операции возвращает ту же серию.
* `/api/series/:id/update`: изменение маршрута/времени оставшихся экземпляров без заявок. Серия с активными заявками отклоняется с 409. Старые даты и первоначальная граница не продлеваются.
* `/api/series/:id/cancel`: явная отмена будущих дат с уведомлениями. Отдельная дата отменяется обычным API поездки. Продление — новая серия с отдельным подтверждением.
* Технические поля дорожного расчёта удалены из пользовательской формы. Расчёт выполняется автоматически. Неудача предлагает уточнить адрес/повторить; новая форма не публикует выдуманную длительность. API старых клиентов с ручным временем сохранён.

## Миграции и данные

`migrations-v5.mjs` делает online backup с integrity_check до добавочной транзакционной миграции. Таблица sessions сохраняет прежние три столбца: MFA вынесена в отдельную таблицу, чтобы откат старого серверного кода не ломал вход. Старые поездки имеют series_id=NULL; старые изображения и отзывы не переписываются. При повторном старте миграция не повторяется. Очередь lifecycle_due индексирована; обработка ограничена 100 наступившими поездками, с триггерами постановки при изменениях. Отправка push сохраняет существующий outbox.

Проверьте миграцию на разрешённой изолированной копии до production. Откат кода не означает откат рабочей БД. Не копируйте старый sqlite поверх WAL/SHM. Backup и recovery описаны в deploy/README.md. Копии содержат персональные данные и не должны попадать в GitHub.

## Настройка Яндекс Расписаний

1. Владелец подключает API Расписаний, проверяет бесплатную квоту, совместимость рекламы и допустимый временный кэш: https://yandex.ru/legal/rasp_api/ru/.
2. В защищённый существующий `/etc/po-puti/po-puti.env` вносятся поля из deploy/features-v5.env.example. Ключ не передаётся в браузер/APK. Нулевая квота, TTL или неподтверждённая лицензия оставляют адаптер выключенным. Укажите лимит ниже предоставленного бесплатного предела с учётом всех потребителей ключа. Лимит приложения — скользящие 24 часа, без платного fallback.
3. Расписания и каталог хранятся только в отдельной SQLite :memory:, не попадают в пользовательскую БД и её резервные копии; истёкшие записи очищаются. После рестарта каталог загружается снова, учитывайте это в квоте. Первый поиск станций загружает временный каталог. Истечение TTL требует обновления. Никакого публичного demo provider и автоматического перехода на платный тариф.
4. Ключ отправляется только в Authorization разрешённому HTTPS API, редиректы запрещены, ответы ограничены по размеру, 429 вызывает паузу.
5. При отсутствии подтверждённой покупки показывается именно «Информация о покупке билета отсутствует». Поля контактов/URL перевозчика из API не превращаются в билетные ссылки. Администратор может проверить конкретный thread/date/from/to через `/api/admin/bus-purchase` с sourceUrl, validUntil и обязательной причиной; это аудируется.

Автобусы не попадают в rides, не получают брони, мест, чата, звонков или отзывов приложения. Авторизация для бесплатного поиска не требует платной подписки. В интерфейсе и документе источников есть атрибуция. Для настольной выдачи адаптер получает copyright из API, извлекает только проверенный URL официального iframe и размещает баннер с текстом. Произвольный HTML от провайдера не вставляется. Перед боевым включением проверьте фактический формат и доступность официального баннера.

## Два рекламных места

Места search/results независимы: после формы и после пятого результата (или после короткого списка). PWA использует веб-РСЯ; Android — официальный Mobile Ads SDK 8.6.0 и нативные BannerAdView, не HTML-рекламу WebView.

Веб-код и нативный экран используют одни серверные DTO. Нативный экран поиска управляется bridge, отправляет события общему JS-контроллеру и открывает прежние экраны поездок. Не дублируйте правила мест, завершения или отзывов в Java.

Площадки сайта и приложения должны пройти модерацию. Владелец отдельно вводит четыре ID вне репозитория; эти ID по природе публичны на клиенте и не являются секретными API-ключами. ADS_ENABLED и ADS_TERMS_CONFIRMED включаются только после принятия условий и утверждения политики.

До согласия SDK не инициализируется и веб-код не загружается. Точная локация и пользовательские тексты в таргетинг не передаются. Android test mode использует официальный demo-banner-yandex; PWA в test mode не запрашивает боевые объявления. Сбой/no-fill скрывает слот, без повторного запроса в callback ошибки. Перерисовка поисковых результатов не должна обновлять уже созданные объявления.

Веб-реклама не включается в административной сессии. Переход с рекламы поиска к входу, профилю, чату или другим приватным формам выгружает документ с рекламным кодом до отрисовки этих форм. Это сокращает доступ стороннего кода к интерфейсу; условия доверия поставщику всё равно требуют проверки.

Для PWA задайте точные официально необходимые HTTPS origins в ADS_WEB_CSP_ORIGINS и проверьте CSP на тестовой площадке. Не разрешайте `*`, unsafe-eval или HTTP ради рекламы. Контроль правильной маркировки, erid и договорных обязанностей — обязательный этап перед боевыми показами. Реальные показы и клики в автоматических тестах запрещены.

## Безопасность и оставшиеся условия выпуска

* MFA хранит секрет AES-GCM с отдельным внешним ADMIN_MFA_ENCRYPTION_KEY. Настройка требует повторного ввода пароля, код проверяется с защитой от повтора. Подтверждение административного фактора действует восемь часов; повторное подтверждение доступно в профиле, включение и подтверждение аудируются без записи секретов. Сначала настройте и проверьте MFA владельца, затем ADMIN_MFA_REQUIRED=true; не включайте обязательность без способа восстановления. Ключ нельзя менять без плана переноса. Для аварийного восстановления владелец может выполнить scripts/reset-admin-mfa.mjs с явным DATA_DIR, --user-id и --reason: создаётся закрытый backup, отзываются сессии и сохраняется аудит. Скрипт не запускается при обычном старте/релизе.
* Android хранит сессию шифрованно с Android Keystore и отключённым backup. Старый localStorage-токен переносится при запуске; для старой оболочки сохранена совместимость. Во время работы WebView всё ещё использует токен в памяти: это не полная защита от XSS и не схема коротких access/refresh tokens.
* Лимиты на записи и API добавлены по пользователю; nginx ограничивает вход. Это не защита от объёмного сетевого DDoS. Измерения производительности выполняются на стенде.
* Фото остаются необязательными, ссылки проверяются по владельцу, повторное содержимое переиспользуется в аккаунте. Новые загрузки декодируются sharp с пределом 20 Мп и двумя параллельными обработчиками, уменьшаются, очищаются от EXIF и нормализуются в JPEG. Старые файлы не переписываются.
* В v6 добавлено самостоятельное удаление через `/api/account/delete` с повторным паролем и подтверждением. Старая очередь deletion-request автоматически не исполняется. Поведение, защита резервных копий и оставшиеся условия магазина описаны в [RELEASE-COMPLETION.md](RELEASE-COMPLETION.md).
* Политика privacy.html содержит честный статус подготовки. Владелец должен утвердить и заполнить оператора, контакты и сроки до магазина/рекламы. Не выдавайте черновик за юридически утверждённый документ.
* Бесплатный геокодер Яндекса: отдельно проверить §§5.1.6 и 6.6.1 https://yandex.ru/legal/maps_api/ru/ применительно к хранению координат и использованию с BRouter. Данные не удалять и действующий ключ не менять без согласованного решения.
* FCM требует Firebase-проект и внешние сервисные credentials. Для устройств RuStore без GMS нужно отдельно выбрать и проверить поддерживаемый push-транспорт. Реальная фоновая доставка на устройства не заявляется проверенной одним тестом bridge.

## Android и RuStore

Нативные добавления хранятся в native/android, генерация оболочки воспроизводима через scripts/prepare-android.mjs после `npx cap add android`, затем `npx cap sync android`. android/ остаётся disposable; кастомные файлы и настройка Manifest/Gradle находятся в Git и накладываются идемпотентно.

Сохраните существующий пакет ru.poputi.app. Прежде чем собирать релиз, получите из старой карточки/установленного APK публичный SHA-256 сертификата и максимальный versionCode. Не создавайте новую карточку и не меняйте подпись для обхода проблемы обновления. Не предлагайте пользователям удалять прежнее приложение.

Workflow android-release-candidate.yml после Verify и Android создаёт только unsigned APK. Это не установочный релиз и не публикация. Keystore и пароль находятся вне GitHub, на доверенном узле/во внешнем защищённом хранилище. Подпишите там стандартным apksigner, затем проверьте файл:

```sh
ANDROID_PREVIOUS_VERSION_CODE='<публичный прежний номер>' \
ANDROID_PREVIOUS_CERT_SHA256='<публичный SHA256 прежнего сертификата>' \
node scripts/check-android-release.mjs /защищённый/путь/app-release.apk
```

В PATH должны быть apksigner и aapt из Android SDK; при необходимости задайте APK_SIGNER/AAPT через проверенную конфигурацию (имя переменной скрипта: APKSIGNER). Проверка не принимает приватные ключи. Она отклоняет debug, неверный пакет, нерастущий номер и другую подпись. Затем проверьте обновление поверх старой версии с сохранением данных.

Релиз в RuStore блокируется до согласования удаления/политики, проверки прежней подписи, реальных устройств, уведомлений без GMS и модерации рекламной интеграции. Ничего в магазине этим обновлением автоматически не отправляется.

## Проверки

`npm run verify`, Chromium и WebKit через `npm run test:browser`. Новые tests/features-v5.mjs проверяют атомарную серию, последний слот, миграцию, DTO автобусов, квоты и MFA; browser-unified-v5.mjs проверяет две клиентские конфигурации. Android CI собирает debug и unsigned release, проверяет итоговые Manifest, разрешения, запрет HTTP, отключённые backup/автоинициализацию рекламы, сравнивает все упакованные веб-файлы и запускает настоящий WebView/bridge на эмуляторе. Тестовые данные находятся только в временных каталогах.

Перед разрешённым production-релизом: изолированная репетиция миграции/восстановления, review PR, все проверки того же SHA, внешние настройки, отдельное разрешение владельца. Слияние main в текущем проекте может автоматически запустить deploy — не сливайте этот PR без согласования публикации.

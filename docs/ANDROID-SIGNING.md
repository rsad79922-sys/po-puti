# Подписанный Android APK для прямого скачивания

Отдельный workflow `android-direct-release.yml` собирает `ru.poputi.app` из main.
Первый прямой выпуск: **1.0.1 (4)**. Заявка **1.0.0 (3)** в RuStore, её APK,
сертификат и настройки публикации не меняются. В workflow нет загрузки в RuStore.
Каждый последующий публичный выпуск должен увеличивать versionCode.

## Где находится постоянный ключ

Создаётся при первом запуске на VPS, если защищённого ключа ещё нет:

* `/etc/po-puti/android-signing/po-puti-release.p12` — зашифрованный PKCS12 keystore;
* `/etc/po-puti/android-signing/store-password` — случайный пароль, root:root, 0600;
* `/etc/po-puti/android-signing/certificate.pem` — публичный сертификат;
* alias: `po-puti-direct-release`.

Каталог имеет root:root, 0700. Приложение и веб-сервер не имеют доступа к ключу.
Новый RSA-ключ — 4096 бит, срок сертификата — 10 000 дней. Повторный запуск
использует тот же ключ. При неполном хранилище, небезопасных правах, ссылках или
несовпадении сертификата сборка останавливается; автоматической замены ключа нет.

**Новая подпись не совместима для обновления APK с другой подписью.** Этот прямой
выпуск не заменяет подпись существующей заявки RuStore. Не удаляйте установленное
приложение ради обхода проверки подписи без сохранения нужных данных.

## Резервная копия вне VPS

На сервере автоматически создаётся дополнительная зашифрованная копия keystore:
`/var/backups/po-puti-android-signing/po-puti-release-<начало SHA256 сертификата>.p12`.
Её права — root:root, 0600. Это защита от случайного повреждения файла, но не от
потери VPS. Скопируйте этот `.p12` по защищённому SFTP/SSH в своё зашифрованное
резервное хранилище **вне VPS**. Пароль из `store-password` сохраните отдельно в
менеджере паролей. Сохраните также alias и публичный сертификат. Не публикуйте
ключ/пароль в GitHub, переписке, скриншотах терминала или открытых каталогах сайта.
Без ключа и пароля обновления с этой подписью будет невозможно подписать.

## Как запускается сборка

GitHub Actions → **Signed Android APK for direct download (no RuStore upload)** →
Run workflow, ветка main, versionCode не меньше 4, versionName `1.0.1` для первого
выпуска. `publish_download=false` сохраняет только готовый артефакт;
`publish_download=true` после успешных проверок размещает APK на существующем сайте.
Используется уже настроенный root SSH-доступ, с проверкой отпечатка хоста VPS.

1. Verify проверяет сервер/PWA, зависимости, браузеры и сборку.
2. На runner собираются release и отдельный instrumentation APK. Релиз не
   debuggable; код приложения одинаков с PWA, API — `https://vputipoputka.ru`.
3. APK выравниваются и передаются на VPS. Подпись выполняется там; пароль
   передаётся keytool/apksigner через закрытый файл, не через argv или журнал.
   Закрытый ключ и пароль не передаются в GitHub, Secrets или артефакты.
4. На runner возвращаются только подписанные APK и публичные сведения. Проверяются
   пакет, версия, SHA-256 файла/сертификата, подпись и совпадение ресурсов PWA.
5. Тот же release APK устанавливается на Android 15 и Android 11/AOSP без GMS.
   Instrumentation APK подписан тем же ключом и проверяет настоящий release.
6. Тест проверяет запуск, отсутствие debug-режима/баннера внутри APK, вход в
   production API и поиск через нативную Android-форму. На каждом эмуляторе
   создаётся только свой временный `qa_android_*` аккаунт; его пароль генерируется
   в памяти устройства. В `finally` этот аккаунт обезличивается через его собственный
   авторизованный API. Чужие аккаунты/поездки не изменяются; тестовые поездки не
   публикуются. Пароли, токены, записи пользователей и снимки экранов не выводятся.
7. После двух успешных установок/сценариев создаётся артефакт
   `po-puti-signed-release`: `po-puti-release.apk`, `release-info.json`,
   `certificate.pem`, `SHA256SUMS`, публичные результаты тестов.

## Размещение на сайте

При `publish_download=true` APK атомарно устанавливается в
`/var/lib/po-puti-downloads/po-puti.apk`. Каталог root:poputi 0750, файл root:poputi
0640: веб-сервис читает APK, но не может заменить его. Прежний APK и окружение
резервируются в закрытом `/var/backups/po-puti-android-publish`.

В `/etc/po-puti/po-puti.env` задаются каталог `ANDROID_APK_DIR=/var/lib/po-puti-downloads`
и единственная настройка ссылки `ANDROID_DOWNLOAD_URL=https://vputipoputka.ru/downloads/po-puti.apk`.
Сервис перезапускается, проверяются
health, конфигурация и размер файла. При ошибке возвращаются прежний APK и
окружение. БД, пользовательские фотографии и ключи других API не заменяются.
Внешний runner дополнительно скачивает публичный APK и сверяет SHA-256.

Для перехода на RuStore позднее достаточно изменить `ANDROID_DOWNLOAD_URL` на
публичную карточку. Подробности баннера и общих ссылок: [ANDROID-DIRECT-DOWNLOAD.md](ANDROID-DIRECT-DOWNLOAD.md).

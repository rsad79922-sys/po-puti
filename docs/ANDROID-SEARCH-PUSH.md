# Поиск Android и фоновые уведомления

Поиск остаётся нативным экраном, чтобы сохранялись два настоящих рекламных
размещения SDK Яндекса. Цвета, округлые поля, карточки и нижняя навигация
согласованы с общей PWA. Все запросы идут на прежний сервер и в прежнюю БД.
Фильтры «Все», «Попутка», «Автобусы» сохраняют маршрут, дату и выбранные станции.

Дата отображается как «20 ноября». Нажатие открывает только день и месяц.
В API передаётся полноценная дата: выбирается ближайшее наступление выбранного
дня, включая следующий год. Несуществующее число при смене месяца ограничивается
последним днём месяца. Ручного ввода ISO-даты и поля года нет.

## Настройка настоящей доставки

Интеграция в APK сама по себе не означает доставку. На момент подготовки изменений
владелец сообщил, что проектов Firebase/RuStore Push ещё нет. Нужны внешние настройки;
проверки с фикстурами и AOSP не являются доказательством облачной доставки.

1. В https://console.firebase.google.com/ создать бесплатный проект Spark
   без привязки платного тарифа. Добавить Android-приложение **ru.poputi.app**.
2. Скачать `google-services.json`. Сохранить весь JSON в GitHub Actions Secret
   **FIREBASE_ANDROID_CONFIG_JSON**. Это клиентские идентификаторы, а не закрытый
   ключ сервера. Разрешить Firebase Cloud Messaging API v1 в этом же проекте.
3. В настройках проекта → сервисные аккаунты получить JSON сервисного аккаунта
   с минимальными правами отправки FCM (`Firebase Cloud Messaging API Admin`).
   Сохранить JSON только в GitHub Actions Secret **FCM_SERVICE_ACCOUNT_JSON**.
   Не присылать файл в чат и не коммитить. Ограничить доступ к Secrets.
4. После выпуска кода на сервер запустить workflow **Configure protected Firebase
   Android push** из `main`. Он проверяет соответствие проекта и пакета, OAuth
   и `validate_only` FCM без отправки сообщений. Настройки передаются по SSH stdin,
   хранятся в `/etc/po-puti/firebase-push/` (root:poputi, 0750/0640), вне сайта
   и репозитория. Есть приватная резервная копия настроек и откат при провале health.
   Существующие VAPID, геокодер, БД и загрузки не изменяются.
5. В новой версии APK войти → Профиль → «Включить уведомления» и разрешить их
   в Android. Публичные параметры клиента поступают из защищённого API;
   пересборка APK для первого подключения Firebase не требуется.
6. На двух тестовых аккаунтах проверить заявку/чат/подтверждение поездки при
   свёрнутом приложении и заблокированном экране, переход к нужной поездке,
   отсутствие старых уведомлений после выхода и доставки чужому аккаунту.

FCM требует доступных Google Play Services. Для устройств без GMS остаётся
официальная интеграция **RuStore Push**: необходимы собственный проект, публичный
`RUSTORE_PUSH_PROJECT_ID` при сборке APK и серверный `RUSTORE_PUSH_SERVICE_TOKEN`
в защищённом env-файле. На устройстве должна проходить проверка доступности SDK
RuStore; одна установка AOSP этого не обеспечивает. При недоступности RuStore
приложение использует FCM, если он настроен, но не обходит отказ в разрешении.

Android принудительно останавливает доставку после системной команды
«Остановить приложение» до следующего запуска. Энергосбережение производителя
может задерживать доставку. Обычное сворачивание не требует открытого WebView:
сообщение обрабатывает нативный сервис.

## Защита уведомлений

Оба транспорта используют data-only сообщение с идентификаторами события и
получателя. Нативный сервис проверяет согласие, текущую сессию из Android Keystore,
получателя и дубликаты до показа. На экране блокировки показывается только
общий текст. Выход очищает уведомления и локальное разрешение доставки.
Сервер сохраняет очередь, повторы и отзыв недействительных токенов.
Закрытый сервисный ключ никогда не передаётся APK или браузеру.

## Проверки выпуска

`npm run verify`, браузерные сценарии Chromium/WebKit; модульные тесты календаря
и политики push; реальные запуск/поиск/подпись на эмуляторах Android 15 и Android 11.
Workflow Android сохраняет снимки поиска, пустого результата и окна дня/месяца
при ширине 320 dp и увеличенном шрифте. APK публикуется только после проверок
под прежней подписью, с увеличенным versionCode. Старая заявка RuStore не меняется.

# Поиск «Все / Попутка / Автобусы» и «Ищу попутку»

Изменения готовятся в отдельной ветке. Не сливать в main без разрешения владельца:
main автоматически развёртывается. Действующий APK и ключ подписи не изменяются.

## Аудит

Сервер уже поддерживал type=all/private/bus. Клиенты ограничивали выбор двумя
вкладками. Модель бронирований requests привязана к поездке водителя, поэтому
пассажирские объявления выделены в отдельные таблицы и API. Android использует
нативный поиск и общий WebView для остальных экранов; оба слоя изменены.

## Реализация

Три горизонтальных фильтра, выделение активного, сохранение маршрута/даты.
«Все» объединяет частные поездки и реальные ответы Яндекс Расписаний; ошибки
автобусного провайдера не скрывают частные поездки. Справочные автобусные карточки,
атрибуция и отдельные ссылки покупки сохранены.

Главная содержит «Ищу попутку» и «Заявки пассажиров». Публикация включает маршрут,
дату, желаемое время, часовой пояс отправления, 1–7 пассажиров и комментарий.
Собственный список показывает историю, позволяет отмену и изменение комментария.
Для изменения остальных условий отменяют старую заявку и публикуют новую.
Водитель выбирает свою подходящую поездку. Сервер повторно проверяет владельца,
маршрут, дату, доступность и свободные места. Предложение уведомляет пассажира;
бронирование и доступ к контактам выполняются через существующие правила поездки.
Предложение само по себе не резервирует места.

API требует вход, принимает существующие cookie/CSRF и Android Bearer сессии:
* GET /api/wanted-config — состояние функции;
* GET /api/wanted?from=…&to=…&date=…&offset=… — 50 записей + nextOffset;
* GET /api/wanted?mine=1 — свои заявки;
* POST /api/wanted — публикация;
* POST /api/wanted/:id/cancel или /update — владелец; update меняет комментарий;
* POST /api/wanted/:id/offer {rideId} — предложение собственной поездки;
* POST /api/admin/wanted {enabled:boolean} — администратор, существующая MFA-защита,
  аудит. Кнопка находится в админ-панели.

Отключение запрещает публичные операции на сервере, скрывает форму/список/кнопки.
Открытый клиент обновляет состояние каждые 15 секунд; сервер запрещает создание
немедленно. Включение восстанавливает сохранённые записи. Истёкшие заявки переходят
в completed в конце указанной даты в часовом поясе отправления, без удаления.

Защита: не больше 5 активных заявок, 10 публикаций в сутки, интервал 60 секунд,
30 новых предложений водителя в сутки, общий лимит запросов, защита от дублей.
DTO не содержит ID автора, телефона, логина или адреса почты. Публичный текст
проверяется на телефоны, email, ссылки и контактные приглашения; клиент экранирует
текст. Как любой текстовый фильтр, это не заменяет модерацию намеренной обфускации.
Удаление аккаунта обезличивает его объявления и удаляет предложения этого водителя.

## Миграция и выпуск после отдельного разрешения

migrateWanted вызывается при старте нового сервера, создаёт отдельную проверенную
SQLite-копию в DATA_DIR/migration-backups с правами 0600, затем транзакционно
создаёт таблицы/индексы/триггер. Старые таблицы и записи не изменяются. Повторный
запуск не создаёт дубликаты. В этой работе миграция выполняется только на тестовых
базах: рабочая база не меняется.

Перед будущим выпуском: успешные Verify и Android CI, резервная копия рабочей БД,
затем отдельно разрешённое развёртывание сервера/PWA. Новый Android APK должен
иметь versionCode выше действующего 4 и использовать существующий постоянный
keystore. Подписанный выпуск не запускать без подтверждения владельца.

## Проверки

npm run verify; npm run test:browser для Chromium и WebKit. Новые тесты:
passenger-wanted.mjs (API, сохранность данных, миграция, лимиты, права, предложения,
отмена/завершение) и browser-wanted.mjs (мобильные PWA/Android bridge, форма,
ошибки, фильтры, админ-переключатель). Android CI проверяет сборку debug/release,
совпадение ресурсов, разрешения и native bridge на Android 15 и AOSP 11.

# Прямое скачивание Android с vputipoputka.ru

Модерация RuStore для этого способа распространения не требуется. PWA остаётся
доступной по тем же адресам. Ссылку на поездку (`/ride/ID` или `/#/ride/ID`)
можно отправлять всем: она открывает поездку и сохраняет её как цель при входе.
Автоматических перенаправлений на APK, магазин или запуск приложения нет.

## Единственная настройка ссылки

`ANDROID_DOWNLOAD_URL` в `/etc/po-puti/po-puti.env`:

```ini
ANDROID_DOWNLOAD_URL=https://vputipoputka.ru/downloads/po-puti.apk
```

При пустом или некорректном адресе баннер скрыт. Разрешены только абсолютные
публичные HTTPS-адреса без логина/пароля. Значение отдаётся без авторизации через
`GET /api/public-config`; ключи API и другие секреты в него не помещать.
После изменения настройки: `sudo systemctl restart po-puti`.

Баннер виден только в браузере Android. Он скрыт на iPhone/iPad/компьютере,
в установленной PWA, Capacitor APK и Android WebView/TWA. Закрытие сохраняется
на время текущей вкладки через sessionStorage; при недоступном хранилище — до
перезагрузки страницы. Баннер расположен в обычном потоке под шапкой, не
перекрывает подачу заявки. Скачивание начинается исключительно по нажатию;
открытая поездка остаётся на месте. Service Worker не обрабатывает `/downloads/`.

## Получение подписанного APK

Релиз для прямого скачивания собирает отдельный workflow
`android-direct-release.yml`: версия первого прямого выпуска **1.0.1 (4)**,
пакет `ru.poputi.app`. Постоянный ключ создаётся и используется только в закрытом
каталоге VPS. GitHub получает подписанный APK и публичный сертификат.

[Расположение ключа, резервная копия, повторная сборка и проверки Android](ANDROID-SIGNING.md).
Заявка RuStore **1.0.0 (3)** остаётся без изменений. Новая подпись не позволяет
обновить APK, подписанный другим ключом; существующие данные не удаляются ради
обхода этого ограничения. Одобрение RuStore для прямого скачивания не требуется.

## Подготовка релизного APK

Использовать ту же конфигурацию приложения `ru.poputi.app`, Node 24, Java 21,
Android SDK и `scripts/prepare-android.mjs`, что и в `android-build.yml`.
Сначала должны пройти Verify и Android, включая проверку одинаковых PWA-ресурсов.
Затем собрать `assembleRelease` с защищённой релизной подписью. Параметры
`ANDROID_VERSION_CODE` и `ANDROID_VERSION_NAME` задаются до prepare/sync.
Для обновления существующих установок versionCode должен быть больше прежнего,
а сертификат подписи — тем же. Подписанные APK и keystore не коммитить.

Если сохранился только AAB, он не устанавливается как APK. `bundletool build-apks
--mode=universal` с тем же keystore/alias и закрытыми password-файлами позволяет
получить `universal.apk`. Перед публикацией его также проверить. Без доступа к
прежнему ключу AAB не решает вопрос совместимой подписи.

Проверка готового файла (Android SDK `aapt`/`apksigner` доступны в PATH):

```bash
node scripts/inspect-android-apk.mjs /protected/path/po-puti-release.apk
```

Требуются действительная подпись, `package: ru.poputi.app`, `debuggable: false`,
ожидаемые versionCode и SHA-256 сертификата. Вывод содержит только публичные
сведения о файле/сертификате. Для обновления дополнительно использовать
`scripts/check-android-release.mjs` с известными публичными метаданными прежнего
APK. Проверить установку/обновление на устройстве до выдачи пользователям.

## Куда загрузить готовый APK

Загрузить проверенный подписанный APK на VPS по защищённому каналу, например во
временный `/root/po-puti-release.apk`. Затем в консоли VPS:

```bash
sudo install -d -o root -g poputi -m 0750 /var/lib/po-puti-downloads
sudo install -o root -g poputi -m 0640 /root/po-puti-release.apk /var/lib/po-puti-downloads/po-puti.apk.next
sudo mv /var/lib/po-puti-downloads/po-puti.apk.next /var/lib/po-puti-downloads/po-puti.apk
curl --fail --head https://vputipoputka.ru/downloads/po-puti.apk
```

Публичный адрес: **https://vputipoputka.ru/downloads/po-puti.apk**. Файл хранится
вне checkout и не теряется при выпуске кода. Задайте `ANDROID_APK_DIR=/var/lib/po-puti-downloads`, чтобы
раздача находилась вне каталога данных, доступного приложению для записи.
Без этой настройки сохраняется совместимость с `DATA_DIR/downloads/po-puti.apk`. Выдаётся только этот точный путь; каталог,
кандидат `.next`, БД, резервные копии и ключи остаются недоступны через HTTP.
Ответ: APK MIME, `Content-Disposition: attachment`, `Content-Length`, `no-store`,
GET/HEAD. Отсутствующий/пустой файл возвращает 404. Ключи подписи на сервер
приложения загружать не требуется.

Сравнить SHA-256 загруженного файла с проверенным исходным APK. **Только после
успешной проверки файла и тестов** указать `ANDROID_DOWNLOAD_URL` и перезапустить
сервис. Не включать ссылку на debug/unsigned APK или отсутствующий файл.
Данные пользователей, SQLite, фотографии и настройки API при этом не меняются.

## Позже: переход на RuStore

В той же настройке заменить URL на фактическую публичную карточку, например
`https://www.rustore.ru/catalog/app/ru.poputi.app`, и перезапустить сервис.
Фронтенд, ссылки на поездки и код баннера менять не нужно. Атрибут скачивания
для ссылки магазина не выставляется. Пустая настройка снова выключает баннер.

## Проверки

`npm run verify` проверяет публичную настройку, HTTP-выдачу/HEAD, замену APK,
закрытость приватных файлов и обход Service Worker. `npm run test:browser`
проверяет матрицу платформ, standalone/native, закрытие, отсутствие скачивания
без нажатия, сохранение прямой поездки после входа и доступность подачи заявки.
Скачивание проверяется через настоящий локальный HTTPS с сопоставлением байтов
полученного файла. Однодневный сертификат теста создаётся в приватном `/tmp`,
удаляется после проверки и не устанавливается в системное хранилище доверия.
Android CI проверяет упакованный WebView: баннер внутри APK недоступен.

Пока `ANDROID_DOWNLOAD_URL` пуст, баннер скрыт. Workflow прямого выпуска может
включить ссылку только после проверки подписи и сценариев на двух Android-эмуляторах.

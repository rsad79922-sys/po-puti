# ТЗ v4: маршрутизация, статусы, PWA и Android

Проект остаётся существующим «По пути» (`ru.poputi.app`, Capacitor 7 + общий `www/`, Node 24 + SQLite). Название и действующая палитра сохранены: в загруженном документе они описаны иначе, чем в реальном репозитории. Исходный документ: [unified-v4.md](specs/unified-v4.md).

## Аудит и реализация

В опубликованной v3 автоматического дорожного маршрутизатора и геокодера не было: форма всегда требовала минуты от водителя, API не выполнял маршрутных запросов. Поэтому сетевые ошибки, CORS или неверный ключ не объявляются доказанной причиной прежнего отсутствия расчёта. В v4 браузер обращается только к своему API; внешний провайдер вызывается сервером, его ключ клиентам не передаётся.

| Требования | Код | Проверки |
|---|---|---|
| 0–3: сохранность, UTC, подтверждения, сроки отзывов, необратимость, отдельные автооценки | `server/lifecycle.mjs`, `server/server.mjs`, миграции, общий UI | `lifecycle-v3`, `api-v3-parity`, `browser-v3-parity` |
| 4: Web Push / Android FCM, permission, unread, click, безопасный текст | `server/push.mjs`, `www/sw.js`, Capacitor plugin | `push-v3`, API/browser parity; реальная доставка требует конфигурации/телефона |
| 5–6: админ-панель, роли, аудит, worker каждую минуту | `server/admin-api.mjs`, `scripts/admin-user.mjs`, общий UI | admin/API/browser-тесты; реальные данные, фильтры, пагинация, причины |
| 8: точные статусы календаря и исхода, независимая бронь | `lifecycle.statusLabel`, общий UI | `routing-v4`, `api-v4-routing`, браузеры |
| 9: дорога, точки, километры, UTC ETA, IANA, fallback, история | `server/routing.mjs`, `timezones.mjs`, `migrations-v4.mjs` | HTTP adapters OSRM/Valhalla/ORS/Яндекс, кеш, ошибки/резерв, геокодер/координаты, смена суток/DST |
| 10–11: оба клиента и выпуск | `www/`, Android workflow / native smoke | Chromium/WebKit, native Android bridge, проверка байтов внутри APK, emulator smoke |

Сервер выдаёт точные подписи: до выезда «Поездка запланирована»; до ETA «Поездка в пути (расчётно)»; после ETA до +1ч «Ожидание подтверждения после прибытия»; затем не ответившему участнику «Подтвердите, состоялась ли поездка». После ответа кнопки скрываются; «Да, состоялась» немедленно открывает форму отзыва. Принятая заявка остаётся «Подтверждена» при изменении календарного статуса. Участнику, уже ответившему, показывается собственный ответ и исход/ожидание ответов остальных.

Автоматический маршрут основан на дорожном ответе провайдера. Координаты не используются для вычисления расстояния по прямой или выдуманного времени. Поддерживаются до 10 точек, включая конкретные посадку/высадку и 8 промежуточных точек. Известные города разрешаются как **явно подписанный центр города**; конкретный адрес без геокодера не подменяется центром. Неоднозначный геокодер требует выбора адреса пользователем. Можно явно ввести `долгота, широта`.

IANA-зоны определяются по координатам (`tz-lookup`). UTC отправления вычисляется на сервере из местных даты/времени; несуществующее время при DST отвергается, неоднозначное требует смещения. Прибытие показывается в зоне назначения с датой. Время устройства не определяет права, ETA или публикацию отзывов. Длительность округляется вверх до полной минуты; ETA является оценкой без обещания пробок/фактического прибытия.

Дорожный кеш живёт час, геокодер — сутки в приватной БД. Каждый запрос имеет таймаут 3,5с, не более двух попыток на провайдера, общий дорожный бюджет 12с. HTTP 400/401/403/404/429 не повторяются подряд; при наличии используется резерв. Для внешних адаптеров UI имеет ограниченное ожидание; для собственного BRouter — не позднее 40с и предлагает ручные минуты. При успехе ручное поле скрыто и не обязательно. В `/admin` → «Система» видны безопасные коды ошибок и поездки без ETA, без ключей/ответов провайдера.

Сервер хранит расчёт как quote, привязанный к аккаунту, исходным точкам, адресам, дате/времени (30 минут). Клиент не может подменить длительность или километраж. Изменение формы сбрасывает quote; публикация со старым расчётом возвращает 409. До выезда водитель может менять маршрут и время через общий UI/API, с обязательной причиной и append-only `ride_eta_history`. Принятые пассажиры сохраняются и получают уведомление. После выезда пересчёт запрещён, в том числе прямым API. Старые поездки не пересчитываются и не получают задним числом автоматические оценки.

## Настройка рабочего маршрутизатора

Дополнительные адаптеры (не выбранный владельцем бесплатный основной вариант): собственный OSRM/Valhalla или аккаунт производственного OpenRouteService/Яндекс с квотами и подходящими условиями использования. Публичные demo OSRM/Valhalla запрещены конфигурацией и не являются резервом. Самостоятельная обработка карты всей России требует значительных RAM/диска; установка на VPS не выполняется вслепую.

Создать `/etc/po-puti/routing.env`, root:poputi 0640, **вне Git**, например для своего OSRM:

```ini
ROUTING_PROVIDER=osrm
ROUTING_URL=https://YOUR_OWN_ROUTER
# Опциональный собственный резерв:
# ROUTING_FALLBACK_PROVIDER=valhalla
# ROUTING_FALLBACK_URL=https://YOUR_OWN_VALHALLA
# Собственный/договорной Nominatim-совместимый геокодер:
# GEOCODING_URL=https://YOUR_GEOCODER/search
```

Для OpenRouteService:

```ini
ROUTING_PROVIDER=ors
ROUTING_URL=https://api.openrouteservice.org
ROUTING_API_KEY=SET_PRIVATELY_ON_SERVER
```

ORS также используется для поиска конкретных адресов. Ключи резервного ORS задаются `ROUTING_FALLBACK_API_KEY`. URL и ключи принимаются только из серверной конфигурации, не из запроса пользователя. Перенаправления провайдера запрещены. Не класть секреты в чат, APK, PR или логи. Не оформлять платную подписку без решения владельца.

Через `sudo systemctl edit po-puti` добавить:

```ini
[Service]
EnvironmentFile=/etc/po-puti/routing.env
```

Затем `sudo systemctl daemon-reload` и `sudo systemctl restart po-puti`. Войти обычным аккаунтом, выбрать реальные адреса Москвы/Твери, Москвы/Екатеринбурга, добавить промежуточный пункт. Проверить длительность, километры, зону/дату прибытия и отсутствие обязательного ручного поля. Если провайдер/ключ отсутствует, API честно возвращает `available=false`, UI использует `eta_source=manual` и не придумывает километраж. Наличие адаптера и тестового HTTP-провайдера **не доказывает наличие настроенной внешней услуги**.

## Миграция и выпуск

1. Чистая установка Ubuntu 24.04/HTTPS/systemd/journald/backups: [deploy/README.md](../deploy/README.md). Для обновления применяется существующий Verify → backup → выпуск → health → откат кода/зависимостей.
2. Перед DDL v4 создаёт и проверяет `migration-backups/before-routing-v4-*.sqlite`. Только новые колонки/таблицы, без удаления прежних строк. Версия маршрутизации хранится **отдельно** в `routing_schema`, базовая `lifecycle_schema=3` сохранена для технического отката к v3. Прежние worker/отзывы не получают фиктивных сроков.
3. До merge запустить `Private migration rehearsal` на ветке `feature/unified-v4-routing`. На VPS только приватная копия рабочей БД, исходник read-only; хеши исходных записей, integrity/FK/уникальность, worker на копии без push. В логах только итог и наличие маршрутизаторных переменных, без значений. Копия остаётся в `/var/backups`, не экспортируется.
4. `npm ci --ignore-scripts`, `npm audit --audit-level=moderate`, `npm run verify`, `npm run test:browser` для Chromium/WebKit; Android CI собирает APK, сверяет шесть PWA-файлов в APK и запускает реальную Activity/WebView/native bridge на эмуляторе API 35. Браузерные сквозные тесты используют отдельную SQLite и локальный HTTP-провайдер; production-записи для них не создаются.
5. Merge прошедшего проверки PR в main автоматически публикует проверенный SHA. Проверить локальный `/api/health`, внешний HTTPS, точный release SHA и систему/очереди в админке. Откат — код и прежние node_modules, без подмены живой DB/WAL/uploads. Восстановление данных только отдельной офлайн-процедурой владельца.

Новые поля: `route_distance_m`, `route_calculated_at`, `departure_timezone`, `destination_timezone`, `route_points_json`; новые таблицы: `routing_schema`, `routing_cache`, `route_quotes`, `ride_eta_history`, `routing_diagnostics`. Старые контракты с явным UTC offset и ручными минутами сохранены; старые APK нужно обновить для нового UI, серверные ограничения действуют и для них.

## Администратор, push и остающиеся внешние условия

Первый администратор назначается по **существующему ID** через `scripts/admin-user.mjs`, с backup и аудитом; публичной регистрации admin и пароля bootstrap нет. Команды VAPID, FCM, worker и роли: [LIFECYCLE-V3.md](LIFECYCLE-V3.md).

```sh
cd /opt/po-puti
sudo -u poputi env DATA_DIR=/var/lib/po-puti node scripts/admin-user.mjs --user-id EXISTING_USER_ID --reason 'Владелец проверен через консоль'
sudo -u poputi env DATA_DIR=/var/lib/po-puti node scripts/run-jobs.mjs
sudo systemctl status po-puti
sudo journalctl -u po-puti -n 100
```

Firebase-проект пока не создан по предыдущему ответу владельца. VAPID/FCM должны быть настроены приватно, физические iPhone/Android для проверки закрытого приложения пока не доступны. Emulator smoke проверяет настоящий APK и bridge, но не доставку внешнего FCM. Системный значок — best effort; внутренний unreadCount обязателен и протестирован.

Известные ограничения: нет MFA внутри приложения, `/state` пока не paginated, прежний Android Bearer хранится в WebView storage, нужен отдельный переход к Keystore. Выпуск в магазин/подпись постоянным release-ключом не выполняется без ключей владельца; CI APK тестовый. Стабильность HTTPS у разных операторов требует наблюдения и не выводится из одного успешного запроса.

## Яндекс: выбранный владельцем сервис

Владелец подтвердил наличие аккаунта и ключа Яндекса. Поддержан официальный HTTP **API Получения деталей маршрута** (прежнее обозначение Routing API): [запрос](https://yandex.ru/maps-api/docs/router-api/request.html), [ответ](https://yandex.ru/maps-api/docs/router-api/response.html), проверены 15.11.2026. Используется `https://api.routing.yandex.net/v2/route`, `mode=driving`, `waypoints` в порядке **широта,долгота**, `departure_time` UNIX UTC. Суммируются метры `length` и секунды `duration` всех steps всех legs; каждый leg обязан иметь `status=OK`. Геометрия не раскрывается клиенту, ключ не попадает в API/БД/журналы. Кеш Яндекса учитывает минуту отправления, чтобы не применять прогноз другой даты.

Серверный `/etc/po-puti/routing.env`:

```ini
ROUTING_PROVIDER=yandex
ROUTING_URL=https://api.routing.yandex.net
ROUTING_API_KEY=SET_PRIVATELY_ON_SERVER
# Для поиска конкретных адресов нужен отдельно разрешённый HTTP Геокодер:
# GEOCODING_PROVIDER=yandex
# GEOCODING_API_KEY=SET_GEOCODER_KEY_PRIVATELY
```

Ключ JavaScript API/HTTP Геокодера **не считается автоматически ключом маршрутизации**. Необходимо проверить название продукта и доступ в кабинете Яндекса, лимиты и ограничения ключа; для серверного вызова ограничения должны разрешать VPS. Ключ геокодера задаётся отдельно; городские центры и явные координаты доступны без геокодера. Ошибка 401/403 не объявляется сетевым сбоем, в админке остаётся безопасный код `http_401/http_403`, форма предлагает ручной режим. Использование и сохранение результатов должно соответствовать договору владельца с провайдером.

После установки проверенной v4 владелец может настроить Яндекс одной командой из доверенной консоли VPS:

```sh
sudo bash /opt/po-puti/deploy/configure-yandex.sh
```

Скрипт запросит ключи скрытым вводом (они не попадут в shell history), проверит реальный маршрут Москва–Тверь без рабочей БД/аккаунтов, сохранит конфигурацию root:poputi 0640 и подключит systemd EnvironmentFile. Ошибочный ключ не активируется. Для отдельной безопасной проверки: `sudo node /opt/po-puti/scripts/probe-routing.mjs /etc/po-puti/routing.env`. Значения ключей в выводе отсутствуют. Не запускать проверку с ключом в аргументах командной строки.

## Выбранный вариант: собственный бесплатный BRouter

По уточнению владельца оплачиваемые API и биллинг Google **не используются**. Основной маршрутизатор — собственный BRouter 1.7.10 с официальным автомобильным профилем `car-fast`, данными OpenStreetMap и закрытым адресом `127.0.0.1:17777`. HTTP Геокодер Яндекса остаётся отдельным бесплатным сервисом адресов (на снимке владельца: 1 000 запросов/сутки); приложение резервирует не более **900 обращений за скользящие 24 часа**, без повторов при отказе и с кешем. Это не глобальная квота аккаунта: обращения других приложений с тем же ключом контролируются в кабинете Яндекса.

До установки проверены реальные дороги на официальных OSM rd5: Москва–Тверь — 186 706 м / 6 516 с; Москва–Екатеринбург — 1 662 924 м / 57 948 с. Это результаты движка по дорожному графу, не расстояние по прямой; они зависят от точек, профиля и версии карты. Пробки не учитываются. Эти локальные измерения отдельно от последующих проверок на VPS.

Проверенная конфигурация VPS: 2 CPU, 4 ГБ RAM, около 53 ГБ свободного диска. Официальный набор тайлов выбранной области России и прилегающих дорог занимает примерно 1,5 ГБ. Установщик выбирает E15..E175/N40..N80 и чукотские тайлы за линией смены даты; непроезжие/несвязанные участки могут не иметь автомобильного маршрута. Загрузка ограничена 3 ГиБ и 350 файлами, требует дополнительно 3 ГиБ свободного диска, использует два потока. Данные скачиваются только с официального HTTPS-хранилища BRouter, а не с публичного сервера расчёта маршрутов.

Версия BRouter закреплена; SHA256 официального ZIP: `023fec3ba997758e8cd7ab9e1bae52e962af3f00b57683e3de86b84ffad01532`. Для собственного воспроизведения после тестов:

```sh
sudo bash deploy/install-free-routing.sh
```

Workflow **Install owned free routing after all tests** сначала проходит reusable Verify и Android APK/emulator, затем устанавливает отдельную службу. Ни БД приложения, ни uploads не изменяются. Новый движок проверяется на отдельном loopback-порту до активации. Проверка двух настоящих дорог обязательна; при неудаче основное приложение продолжает работать. Установщик не перезапускает API: его подключение выполняется последующим проверенным выпуском приложения.

Пути и ограничения:

- `/opt/po-puti-brouter/` — закреплённая программа и профили; root, read-only для отдельного пользователя `poputi-router` без входа в систему;
- `/var/lib/po-puti-brouter/` — только воспроизводимые карты; текущий и предыдущий снимки сохраняются, старые помеченные кеши удаляются только при отсутствии посторонних файлов; пользовательские DB/uploads в этот каталог не помещаются и не открываются;
- `po-puti-router.service` — Java heap 1 280 МБ, MemoryMax 2 ГБ, CPUQuota 100% (одно из двух ядер), один запросный поток; при перегрузке интерфейс предлагает ручную длительность;
- `po-puti-router-maps.timer` — еженедельно в воскресенье 04:20 UTC (09:20 Екатеринбург) с задержкой до 30 минут; карты меняются атомарно, затем движок перезапускается;
- запросы собственному BRouter ограничены 30с, без повторного параллельного запуска; UI завершает ожидание не позднее 40с. Первый дальний маршрут может рассчитываться дольше, повторный использует серверный кеш;
- точные запросы BRouter не сохраняются в stdout-журнале; ошибки службы и обновления карт доступны через journald; в админке — обезличенные коды ошибок, состояние ETA и расход бесплатной квоты.

Проверки и диагностика:

```sh
sudo systemctl status po-puti-router po-puti-router-maps.timer
sudo journalctl -u po-puti-router -u po-puti-router-maps.service -n 100
sudo python3 scripts/probe-brouter.py http://127.0.0.1:17777
sudo node scripts/probe-routing.mjs /etc/po-puti/routing.env
```

Для бесплатного геокодера — **после установки v4** — владелец вводит свой ключ скрыто в консоли:

```sh
sudo bash /opt/po-puti/deploy/configure-free-geocoder.sh
```

Этот скрипт проверяет только публичный адрес, сохраняет ключ вне Git с правами 0640 и **сохраняет собственный бесплатный маршрутизатор**. Ключ не нужно передавать в чат. Без него точные адреса требуют явных координат или ручной длительности; известные города поддерживаются с подписанным центром. Программа не подключает платные тарифы, не вводит карту и не активирует внешние маршрутные ключи.

Лицензии/атрибуция: [BRouter](https://github.com/abrensch/brouter), [OpenStreetMap contributors](https://www.openstreetmap.org/copyright). Источник указан в форме оценки маршрута. При недоступности данных, ошибки движка или превышении его ресурсного бюджета действует ручной fallback, без фиктивного ETA. Возможны неточности OSM, ограничения проезда и расхождение с пробками: это оценка длительности, не навигатор и не доказательство прибытия.

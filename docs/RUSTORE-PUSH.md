# Android: RuStore Push без GMS

Общая серверная база, очередь уведомлений и API сохраняются. Нативный SDK
`ru.rustore.sdk:pushclient:7.5.0` подключён из текущего официального Maven:
https://nexus-external.rustore.ru/repository/maven-rustore-exposed/ .
Документация: https://www.rustore.ru/help/sdk/push-notifications/kotlin-java/7-5-0 .
Прежний адрес artifactory больше не используется.

## Настройки

* `RUSTORE_PUSH_PROJECT_ID`: публичный ID проекта из консоли RuStore. Передаётся
  при сборке через GitHub Secrets того же имени. Он необходим SDK и попадает в
  BuildConfig/APK как публичная настройка. Пустое значение оставляет SDK выключенным.
* На сервере — тот же `RUSTORE_PUSH_PROJECT_ID` и приватный
  `RUSTORE_PUSH_SERVICE_TOKEN` в защищённом env-файле. Сервисный токен никогда
  не передаётся в APK, PWA, публичный API, аргументы команд или артефакты.
* Чтобы получить реальную доставку, нужны созданный проект и подходящее устройство
  с RuStore/разрешённой фоновой работой. Отсутствие GMS само по себе не означает,
  что RuStore Push доступен. Интерфейс отдельно сообщает об этом.

## Поведение

SDK инициализируется только после явного включения уведомлений либо при запуске
после ранее сохранённого согласия. Автоматический InitProvider удалён из Manifest.
Для SDK применяется логгер без вывода токенов/сообщений. Разрешение Android 13+
запрашивается при включении. Реклама Яндекса и её согласие остаются независимыми.

Клиент выбирает RuStore при доступной настройке этой сборки и сервера; токен
регистрируется как `platform=android, provider=rustore`. Без настройки сохраняется
прежняя ветка FCM. Одновременно один device/platform не получает две подписки.
Смена SDK-токена обновляет общий API с текущей Keystore-сессией.

Сервер отправляет data-only сообщение: ID уведомления, ID получателя и безопасный
путь. Имени, телефона, отзыва, переписки и точного адреса в push нет. Нативная сторона
показывает фиксированный общий текст лишь для совпадающего получателя, включённого
согласия и текущей сессии. Проверяются ID, путь и повторы. Это позволяет подавить
задержавшиеся сообщения после выхода или смены аккаунта; автоматическое отображение
notification payload SDK не используется. Переход из холодного запуска ждёт входа
в соответствующий аккаунт. Выход/удаление отзывают локальный допуск и очищают
показанные уведомления; серверная отписка отменяет его outbox.

## Сборка и проверки

`npm run android:add`, `npm run android:sync` воспроизводимо накладывают Java,
Gradle и Manifest. CI проверяет debug/unsigned release, итоговые разрешения,
отсутствие auto-init, одинаковые web-ресурсы, Java unit policy и настоящий
Capacitor-мост на Google APIs/AOSP. Browser-тест проверяет выбор транспорта,
подписку, защиту переходов по получателю и отписку через общую SQLite.

Эти проверки не заменяют получение push в фоне на настоящем устройстве с
настроенным проектом, после перезагрузки, при закрытом приложении и после выхода.
Без ключа подписи и публичной метаинформации предыдущего отправленного APK
подписанную замену для модерации создавать нельзя.

## Проверка отправленного APK без передачи ключей

```bash
AAPT=/путь/к/Android/build-tools/aapt \
APKSIGNER=/путь/к/Android/build-tools/apksigner \
node scripts/inspect-android-apk.mjs /путь/к/отправленному.apk
```

Команда только читает APK и выводит публичные package/version/debug/certificate
и SHA256 файла. Приватный keystore и пароли не требуются. Несколько подписантов
выводятся явно. Не используйте старый debug APK как подписанный выпуск RuStore.

# Проверка «По пути» — 14 ноября 2026

Проверена копия из `po-puti-codex-export.zip` (идентификатор исходного архива: 677c406335b4f196620efaa5808bfc5d3fe3aadc). Рабочий VPS не изменялся. Исправления находятся в приложенном новом архиве.

## Исправления

1. **Неверное число мест.** `/state` выдаёт только заявки текущего участника; раньше клиент вычитал лишь эти заявки из общего числа мест. Теперь API отдельно возвращает `occupiedSeats`, а интерфейс учитывает общий итог без раскрытия чужих заявок.
2. **Фото в Android.** Относительные `/uploads/...` указывали на локальный origin WebView. Теперь загруженные фотографии используют origin общего API; PWA продолжает работать с относительными адресами, превью JPEG сохраняются.
3. **Параллельная публикация с фото.** Во время записи файла другой запрос мог успеть сохранить тот же ключ операции. Повторная проверка внутри транзакции предотвращает ошибку UNIQUE/HTTP 500 и создание нескольких поездок. Ключ восстановленного старого черновика сохраняется до запроса, чтобы сетевой повтор использовал тот же ключ.
4. **Данные после выхода.** Очищаются профили, поездки, переписка, заявки, черновик и данные админки; аналогично обрабатывается истёкшая сессия. Ответ старого запроса админки не применяется к новой сессии. Завершившаяся обработка фото не переносится в другой аккаунт.
5. **События другой вкладки.** Сохранение локальной демонстрации в соседней вкладке больше не заменяет состояние настоящего API-клиента.
6. **Прямые ссылки.** Переход на `/profile`, `/trips`, `/ride/...` и другие разрешённые пути выбирает соответствующий экран. Раньше HTML выдавался успешно, но интерфейс открывал поиск. Для неавторизованного пользователя остаётся экран входа.
7. **Админская карточка.** Поездка из административного списка открывается даже при отсутствии её в обычной выдаче пользователя.
8. **Сбой запуска из сохранённых настроек.** Валидный JSON `null` в `po-puti-ui-v2` вызывал исключение. Добавлена проверка формы сохранённых настроек, поиска и черновика.
9. **Откат обновления.** Убраны замена рабочей SQLite-базы через `cp` и удаление фотографий. Такой откат мог потерять успешные записи и конфликтовать с WAL/SHM. Автоматический откат теперь возвращает только код. SQLite backup выполняется до копирования append-only фотографий, чтобы все ссылки снимка имели файлы в резервной копии. Отсутствие каталога uploads у старой версии не блокирует резервную копию. Права резервных файлов ограничены `umask 077`. Изменённый сценарий проверен на синтаксис; на настоящем VPS не запускался.
10. Обновлены версии загрузки JS (`boot14`) и Service Worker (`network-first-v4`). Полный браузерный сценарий добавлен в WebKit CI.

- Chromium: выбор фото, сжатие JPEG, отправка и отображение;
- `bash -n` для всех shell-файлов deploy.

Команды браузерных проверок в этой среде:

```sh
npm install --no-save playwright
BROWSER_ENGINE=chromium node tests/browser-webkit.mjs
BROWSER_ENGINE=chromium node tests/browser-photo-upload.mjs
node tests/browser-full-flow.mjs
```

Нужен установленный Chromium (`/usr/bin/chromium`, либо `CHROMIUM_PATH`). Имена двух исторических тестов и часть их сообщений содержат WebKit, но здесь они выполнены на **Chromium**. WebKit скачан, однако запуск требует отсутствующих системных библиотек; их установка недоступна без системной аутентификации. Safari и физические телефоны не проверены. В CI предусмотрен WebKit после установки библиотек.

## Публичное приложение и границы проверки

- `https://vputipoputka.ru/api/health` ответил HTTP 200 через доступный сетевой шлюз: `{"ok":true,"backend":"sqlite","version":"0.2"}`.
- Скачанный опубликованный HTML использует `app.js?v=boot12`; опубликованный JS отличается от исправленного. Сервер пока не обновлён этим архивом.
- Прямые соединения из этой среды ограничены: DNS/прямой IP не дали доступа. Ошибки таких запросов не доказывают поломку VPS. Успешный запрос через шлюз также не доказывает отсутствие периодических зависаний у операторов пользователя.
- В предоставленных старых отчётах указан IP **130.49.129.99**, тогда как в текущем сообщении был **139.49.129.99**. Актуальную DNS-запись через независимый резолвер здесь подтвердить не удалось; менять DNS по этому расхождению нельзя.
- Нет доступа к SSH, фактическому nginx/systemd и журналам VPS. Корневая причина ранее описанных периодических TLS-сбоев не установлена и этим изменением не объявляется исправленной.
- Нет нового APK. Исправления Android требуют пересборки из этой версии, а серверные изменения — обновления VPS. Старый архив в `releases/` исторический и не содержит этих исправлений.
- Сохраняются ограничения MVP из README: хранение токена в localStorage, отсутствие системных push, ограниченная масштабируемость `/state` и неуказанная временная зона поездок. Они не устранены этим пакетом.

## Применение

Пакет содержит исходники, тесты и отчёт, без базы пользователей, паролей и node_modules. Перед обновлением работающего сервера нужна согласованная резервная копия SQLite и uploads. Обновлять только код проекта; `/var/lib/po-puti` и `/etc/po-puti/po-puti.env` не заменять файлами архива. Существующий `deploy/release-on-vps.sh` рассчитан на Git checkout main и целевой commit SHA; ZIP сам по себе не запускает этот процесс. После доставки кода на сервер проверить локальный и публичный `/api/health`, затем повторить сценарий на настоящих устройствах.
